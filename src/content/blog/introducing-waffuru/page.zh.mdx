## 为什么是*现在*

对智能的需求没有上限，而支撑它的资源有。扩展推理，光靠新建数据中心和更多电力远远不够，还要让每一单位算力和能源做更多有用的功。下一代基础设施必须让智能的可及性增长得比成本、能耗和环境影响更快。

当电力成为天花板，效率就是你仍能撬动的变量。每瓦 token 数和每个工作负载的成本，是我们还能去优化的指标。效率也不会让需求缩小。每一次提升都会被花在更多的智能上，这就是古老的杰文斯悖论，所以对算力的胃口只会越来越大。

曲线的另一端也在移动。我们认为，大约两年内，运行在人们已有硬件上的模型就会好到足以胜任有意义的工作，因为摩尔定律和 AI 的快速进步仍在不断叠加。

我们预计，每个人都会有一个个人助理，或一整个助理团队，而且它们会彼此对话。人们想要掌握主动权，所以助理必须是你自己值得信赖的延伸：有用，好相处，不吓人。这种关系会像你和手机的关系一样私人。它不该取决于你住在哪里、收入多少或持有什么资历，而要在各地提高人们的收入潜力，就需要开放、本地化的智能获取方式。

## 我们在*打造*什么

四款产品，从底层硬件往上编号。Iron 编译内核，Butter 在内核上运行模型，Waffle 盯着 GPU，Syrup 记得你在做什么。每一款都能单独使用，合在一起，就是本地优先个人助理的基础。

### Iron，内核

[Iron](/products/iron) 就是一份内核定义，四种后端。你用嵌入 Rust 的 DSL 写一个内核，它先转换为共享 IR，再生成 Metal、CUDA、HIP/ROCm 或 Vulkan SPIR-V，版本化的 C 与 Rust ABI 则让你已有的宿主可以直接调用。目前约有 1,139 个内核声明，我们的 HIP 与 Vulkan 测试集 4,164 个用例全部逐位精确通过。下面就是一个 `exp` 内核的完整定义：

```rust title="unary.rs"
#[kernel(bench(op = "unary", subop = "exp", tol = 1e-4))]
pub fn iron_exp<T>(a: Tensor<T>, out: Tensor<T>) {
    let idx = program_id(0);
    store(out[idx], exp(load(a[idx])));
}
```

这些你来写，其余交给 Iron。

### Butter，引擎

[Butter](/products/butter) 是无需 Python 的模型服务：Apple 芯片上用 Swift 搭配 Metal，CUDA 及其他平台用 Rust。它直接从 Hugging Face 加载模型（safetensors、MLX、JANG 和 GGUF），无需转换，并能运行 2 至 8 位量化检查点、混合模型和混合专家模型，以及量化 KV 缓存。`butter serve` 使用 OpenAI API，支持流式输出、工具调用、推测解码和 LoRA。文本、视觉、语音转文字、文字转语音和全模态模型都能运行。没有 Python，没有 JIT。

### Waffle，控制平面

[Waffle](/products/waffle) 让你看清每一块 GPU 和其上运行的每个引擎，从桌下的一台机器，到出租集群的新型云服务商。每台主机运行一个小型 Rust sidecar，上报带签名的遥测数据。它支持 Butter、vLLM、SGLang、llama.cpp 以及其他兼容 OpenAI 的服务器，所以没有锁定。

### Syrup，记忆

[Syrup](/products/syrup) 让你的 AI 记得你在做什么。它对你的笔记和代码做本地检索，用 TurboQuant+ 压缩嵌入向量，同时按关键词和向量搜索，并通过 MCP 返回带引用的结果。

## 我们的*现状*

还早。我们的产品目前是私有的闭源软件，访问需要申请。硬件的情况，直说如下：

- **Apple 芯片，Metal：首要**。每个内核都先在这里编写并调优。
- **NVIDIA，CUDA：其次**。已在 RTX 和 DGX Spark 上投入生产，数据中心 GPU 正在进行中。
- **AMD ROCm 和 Vulkan：可运行**。两者目前都能工作，但都尚未调优。

实际上，这意味着 MacBook 和 Mac Studio、RTX 工作站、DGX Spark、Strix Halo 和新型云服务商的集群，企业级数据中心 GPU 还在路上。我们暂时不引用速度数字。
